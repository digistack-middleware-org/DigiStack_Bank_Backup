## 🔍 Root Cause Analysis

### The Single Configuration Object Responsible

> **The WAS JAAS J2C Authentication Alias — `BankDS_Alias`**
> (Security → Global security → JAAS → J2C authentication data)

This alias stores the **username + password** WAS uses to log in to
PostgreSQL on behalf of the application:

```
App → JNDI DataSource (DigiStack Bank DataSource)
    → JAAS Alias (BankDS_Alias)
    → PostgreSQL (digistack_app @ dsb-db:5432)
```

The alias currently holds the **old password**, but PostgreSQL now
requires the **new rotated password**. Authentication fails with
SQL State `28000` (invalid authorization) → every DB connection fails.

### Why All Seven Symptoms Trace to This One Object

| Symptom                          | Explanation                                        |
|----------------------------------|----------------------------------------------------|
| Home page "Error" / fallback     | App cannot query DB for status values              |
| Login rejected with system error | Login validates user against DB — connection fails |
| App shows green/Started          | WAS runs fine; only DB **connections** fail        |
| Test connection fails (28000)    | Alias password rejected by PostgreSQL              |
| PostgreSQL healthy               | DB is fine — it correctly rejects the wrong creds  |
| Nodes Synchronized               | The **wrong config** synced perfectly to both nodes|
| StaleConnectionException in log  | WAS pool connections dead — bad credentials        |

**Key insight:** One broken credential source → every DB touchpoint fails
while every process stays healthy.

### The Maintenance Action That Caused It

During the maintenance window's **"credential management tasks,"**
the DBA rotated the PostgreSQL password for user `digistack_app`,
but the **WAS JAAS alias was never updated** to match.

- PostgreSQL: password changed ✅
- WAS alias `BankDS_Alias`: still holds old password ❌
- Classic **coordination failure** between DBA and WAS admin.

## 🛠️ Precise Remediation (Step-by-Step)

### Step 1 — Get the correct password
Confirm the **current (rotated)** PostgreSQL password for
`digistack_app` with the DBA. *(In this scenario: `Wasadmin@951951`)*

### Step 2 — Update the JAAS Auth Alias
1. Admin Console: `https://192.168.10.10:9043/ibm/console`
2. **Security → Global security**
3. **Authentication** section → **Java Authentication and Authorization Service**
4. **J2C authentication data**
5. Open **BankDS_Alias**
6. Replace the password with the **correct current password**
7. User ID stays: `digistack_app` (unchanged)
8. **OK → Save** (Master Configuration)

### Step 3 — Synchronize nodes
1. **System administration → Nodes**
2. Select **all nodes** → **Full Resynchronize**
3. ✅ Confirm: *"Synchronization completed successfully."*

### Step 4 — Restart both application servers
1. **Servers → Server Types → WebSphere application servers**
2. Select both → **Stop** → wait for stopped
3. Select both → **Start** → wait for green started

> **Why restart?** The connection pool **caches old credentials**.
> A restart forces WAS to load the corrected alias.

### Step 5 — Verify the fix
1. **Resources → JDBC → Data sources**
2. Check **DigiStack Bank DataSource** → **Test connection**
3. ✅ Expect: *"The test connection operation ... was successful"* on both nodes

### Step 6 — End-user verification
1. Open `http://192.168.10.20/digistack-bank/Home`
   - ✅ `DB Connected` = **Connected**
   - ✅ `System Status` = live value (no fallback)
2. Login as `customer1 / Customer@123`
   - ✅ Login succeeds, session created
3. Check `SystemOut.log`
   - ✅ No new `StaleConnectionException` / `DSRA0080E` entries

## 🛡️ Prevention Recommendations

- 🔄 **Coordinate rotations:** DBA and WAS admin change credentials
  **together** in the same maintenance window.
- 📝 **Credential checklist:** Any password rotation must include a
  "WAS alias updated?" step.
- 🤖 **Monitoring:** Alert on `StaleConnectionException` and
  SQL State `28000` in `SystemOut.log` — catch it before users do.
- 🧪 **Post-maintenance test:** Always run **Test Connection** on all
  Data Sources after any credential-related change.

---

## 💡 Quick Memory Cheat Sheet

- **One alias** feeds all DB connections — one wrong password = app-wide DB failure
- **Green app ≠ working app** — check the Data Source, not just the server
- **Synchronized ≠ correct** — bad config syncs just as fast as good config
- **SQL State 28000** = invalid credentials → suspect the **alias first**
- **Restart required** — pooled connections cache the old credentials
